# Employee REST API Testing with Postman and Newman

Hi, I'm **Joinab Binte Siraj Asifa**. This repository contains my **SQALOGY B3 API testing assignment**.

I tested the [Employee REST API](https://crudapi-o7rr.onrender.com) using Postman. I created positive and negative test cases, executed the collection with Newman, generated an HTML report, and documented the issues observed during testing.

## API Documentation

[View the published Postman documentation](https://documenter.getpostman.com/view/57047052/2sBYHUTfs8)

## What I Tested

I created **110 test cases (TC01–TC110)**, organized into 12 folders:

1. **Login** — valid and invalid login attempts.
2. **Create Employee** — create five employees across five departments and test negative scenarios.
3. **Get Employee Info** — retrieve an employee by ID, test invalid IDs, and requests without a token.
4. **Update Employee Info** — update mobile number and position, then verify the changes.
5. **Delete Employee** — delete an employee and verify that the record is no longer available.
6. **Get All Employees** — check the employee list and record count.
7. **Query Params** — filter employees by mobile number and email.
8. **Validation Probes** — test invalid salary, name, and status values.
9. **Extra Login Tests** — SQL-injection-style input, very long usernames, and token-format checks.
10. **Extra Create Validation** — missing fields, invalid dates, invalid phone numbers, HTML/script-like input, and duplicate emails.
11. **Extra Get and Query Tests** — pagination, department filters, and status filters.
12. **Extra Update, Delete and Final Checks** — additional update/delete scenarios and final verification.

The collection uses the Postman environment `SqalogyB3TestEnv`.

## Test Results

According to the recorded execution summary:

- **Test cases:** 110
- **Passed test cases:** 84
- **Failed test cases:** 26
- **Failed assertions reported by Newman:** 40

The recorded explanation for the 40 failed assertions is that 14 failed test cases had two failed assertions each (status and cleanup checks), while the other 12 had one failed assertion each.

The failures were reviewed and documented as candidate API issues. A failed assertion is not automatically a confirmed product defect; findings should be reproducible and checked against the API requirements.

## Candidate Bugs Identified

The `Bug_Report/` folder contains the defect report and `Jira.csv` export.

| ID | Issue observed | Proposed severity |
|---|---|---|
| BUG-01 | Negative, non-numeric, and very large salary values accepted on create | *High* |
| BUG-02 | Negative and non-numeric salary values accepted on update | *High* |
| BUG-03 | Invalid email format accepted on create and update | *Medium* |
| BUG-04 | Duplicate email accepted when letter case differs | *Medium* |
| BUG-05 | Invalid status handled inconsistently on create and update | *Medium* |
| BUG-06 | First name accepts blank, numeric, and 300-character values | *Low* |
| BUG-07 | Invalid `hireDate` format accepted on create | *Medium* |
| BUG-08 | HTML/script-like input returned or stored without visible neutralization | *Security review required* |
| BUG-09 | Invalid token returns HTTP 403 rather than HTTP 401 | *Low* |
| BUG-10 | Invalid `limit` query value is not rejected | *Low* |
| BUG-11 | Invalid `page` query value is not rejected | *Low* |

*Severity and defect status should be confirmed against the API specification and reproducible evidence. An API returning HTML/script-like text does not by itself prove stored XSS; verify whether it executes in a consuming UI. HTTP 403 instead of 401 is a defect only if the API contract requires 401 for the tested case.

## Installation and Execution

### Prerequisites

Install [Node.js](https://nodejs.org) (LTS recommended). Check that Node.js and npm are available:

```bash
node -v
npm -v
```

### Step 1: Open the project directory

Open Terminal or the VS Code terminal in the project root—the folder containing `package.json`, the collection JSON, and the environment JSON.

### Step 2: Initialize npm (only if needed)

If `package.json` does not exist yet, run:

```bash
npm init -y
```

Your screenshot shows that `package.json` already exists, so you normally do not need to run this again.

### Step 3: Install Newman

```bash
npm i newman
```

### Step 4: Run the collection directly (optional)

```bash
npx newman run SQALOGY_B3_EmployeeApi_Tests_postman_collection.json -e SqalogyB3TestEnv.postman_environment.json
```

Alternatively, if you have a collection URL or secret key:

```bash
npx newman run "[collection URL or secret key]"
```

Do not publish private collection links, passwords, access tokens, or API keys in this README.

### Step 5: Install the HTML reporter

```bash
npm i newman-reporter-htmlextra
```

### Step 6: Create the Reports folder if needed

```bash
mkdir -p Reports
```

### Step 7: Check or create `Reports/report.js`

Your screenshot shows `report.js` inside `Reports/`. If you create or edit it there, use `../` to reference the collection and environment files in the project root:

```javascript
const newman = require('newman');

newman.run(
  {
    collection: require('../SQALOGY_B3_EmployeeApi_Tests_postman_collection.json'),
    environment: require('../SqalogyB3TestEnv.postman_environment.json'),
    reporters: ['cli', 'htmlextra'],
    reporter: {
      htmlextra: {
        export: './Reports/newman-report.html',
        title: 'SQALOGY B3 Employee API - Newman Report'
      }
    }
  },
  function (err) {
    if (err) {
      console.error('Newman execution failed:', err);
      process.exitCode = 1;
      return;
    }
    console.log('Collection run complete. Report saved to Reports/newman-report.html');
  }
);
```

Run this script from the project root so the relative paths work.

### Step 8: Generate the HTML report

Since `report.js` is inside `Reports/`, run this command from the project root:

```bash
node Reports/report.js
```

If you move `report.js` to the project root, use:

```bash
node report.js
```

### Alternative: Generate the report with one Newman command

Run this from the project root:

```bash
npx newman run SQALOGY_B3_EmployeeApi_Tests_postman_collection.json -e SqalogyB3TestEnv.postman_environment.json -r cli,htmlextra --reporter-htmlextra-export Reports/newman-report.html
```

This writes the HTML report to `Reports/newman-report.html`.

### Step 9: Open the HTML report

**macOS**
```bash
open Reports/newman-report.html
```

**Windows PowerShell**
```powershell
start Reports/newman-report.html
```

**Linux**
```bash
xdg-open Reports/newman-report.html
```

You can also open the HTML file in a browser and print it to PDF using **Print → Save as PDF** (`Cmd+P` on macOS or `Ctrl+P` on Windows/Linux).

## Notes

- The API is hosted on a free service, so the first request may be slow while the server wakes up.
- The collection creates and updates records. Re-running it may change employee IDs and record counts.
- Run tests only against an authorized test environment and avoid including real user data in reports.
- If a request fails with an invalid URL, verify the base URL and environment variables.
- Never commit passwords, access tokens, API keys, or other secrets.
